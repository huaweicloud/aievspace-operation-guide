这个案例解决什么真实问题？

近一年的开发工具都在往「Agent 直接操作电脑」走——它要开浏览器、点按钮、看截图、验结果。可你的笔记本是图形界面，云主机通常只有字符终端；给每台云主机装 VNC、配隧道、装客户端，一折腾就是半天，还很难复制给同事。

AI 开发者空间把这件事做成了一个环境模板：KasmVNC Desktop。点「部署」之后，一台带图形界面的 Linux 运行在云端容器里，通过 KasmVNC 以 Web 方式串流到浏览器，服务端不装客户端、不暴露端口、不用配 SSH 隧道；同时它和 AI Shell 共用同一台机器——Agent 敲命令的地方，就是你能看见桌面的那台机器。

核心知识

KasmVNC 是什么

KasmVNC 是 Kasm Technologies 开源的 VNC 服务器，和传统 VNC 最大的差别是「Web 原生」：渲染在浏览器里用 WebAssembly / WebRTC / WebGL 完成，因此不需要安装任何客户端，也不需要 Java 插件或额外的网关。它同时提供双向剪贴板、文件传输、画质与帧率调节，以及水印、剪贴板策略这类管控能力，所以很多企业远程办公、在线实验平台都用它来串流 Linux 桌面。

在 AI 开发者空间里，它被封装成了一个作业环境模板（Job Environment）。平台用 job-env-manager 统一管理这些环境的生命周期——up（部署/启动）、stop（停止）、inspect（查看状态），并且操作是幂等的：重复部署不会报错，已经在运行就直接返回。这点很关键，后面 AI Shell 排查「到底起没起来」用的就是它。

环境管理点「部署」，拉起 KasmVNC 容器
→
Web 桌面浏览器里得到 Ubuntu 图形界面
↔
AI Shell同一台机器，自然语言执行命令
→
直达链接把这一整套打包成 URL 分享

这台桌面里的三条「约定」

镜像自带一份《桌面使用提醒》，三条约定撑起了后面所有操作，值得先抄下来：

文件放哪重要文件放 /root 下，环境重启或升级不会丢
怎么装软件终端执行 get-apps.sh <别名>，别名直接对应应用
装到哪应用落在 /root/Software/<app>/，自带 launch.sh
装错了怎么办get-apps.sh -l 看已装，get-apps.sh -u <别名> 卸载
不会用怎么办直接对 AI Shell 说人话，例如「帮我安装个钉钉」

清单不是写死在前端页面里的，而是沙箱内的配置文件 apps.conf。所以 AI 回答「能装什么」时不是猜，而是先读文件——这也意味着清单会随镜像版本更新。

前置条件

必须

  • 一个华为云账号（已注册即可，不需要充值、不需要实名也能跑通本案例）
  • AI 开发者空间入口：developer.huaweicloud.com/devspace，或直接用本页顶部的带签名直达链接
  • 较新的 Chrome / Edge 浏览器：KasmVNC 依赖 WebAssembly、WebGL、剪贴板 API，请用桌面版浏览器，不要用手机浏览器凑合

建议了解

  • Linux 基础操作（cd / ls / 运行脚本），不熟也没关系，AI Shell 会代劳
  • 知道「环境」和「文件」是两回事：环境可以随时重建，文件要靠 /root 持久化

版本怎么选

版本计费数据适合谁
体验版免费，不消耗额度不保留，时长结束自动回收（约 3 小时）跟着本案例跑一遍、看效果
持久化版按核时计费，初始赠送额度关机自动保存，/root 长期保留要持续开发、留存工程与桌面环境
不用准备的东西：不用装 VNC 客户端，不用开安全组端口，不用配 SSH 隧道，也不用自己装桌面环境。这些都在「部署」那一下里。

实践操作

下面是完整走通的 7 个动作，每一步都给了可复制的内容和「完成标志」。截图来自本次实测。

0

用签名链接一键进入环境

约 2 分钟

直接点本页顶部（或侧栏）的「进入你的开发空间」按钮。这里要讲清楚一个容易误会的点：

这条链接进入的是你自己的环境。它带平台签名，会直接拉起你本人在 AI 开发者空间里的云主机 / 实操环境（首次进入需登录并完成实操入口校验）。所以你在里面部署的 KasmVNC Desktop、装好的 Chrome 与飞书，只属于你这台云主机，不会跳到一个预设好的演示桌面。
一键进入你的开发环境 → 打开即进入你自己的 AI 开发者空间，无需手动配置

打开后页面会显示「正在配置实操环境」，进度条依次经过 验证参数 → 启动 KasmVNC Desktop WebUI → 环境配置完成，通常 1–2 分钟。中途别反复刷新，刷新等于重新排队。

完成标志：右上角出现「保持展开」和剩余时长倒计时（体验版从 03:00:00 开始倒数），说明容器已就绪、可以操作了。
1

在「环境管理」里部署 KasmVNC Desktop

约 2 分钟

左侧工具栏进入 TOOLS → 环境管理。这里把所有可用的作业环境按类型分了组（智能体 / 开发工具 / 数据库 / 基础设备 / 学习），顶部还有搜索框和「未部署 / 运行中 / 异常 / 待开放」的状态统计。

在搜索框输入 KasmVNC，或切到「开发工具」分类找到这张卡片。卡片上的三个标签 VNC Desktop Remote 已经说明它的用途，右下角是「部署」按钮。

点「部署」，等待卡片状态从「未部署」变为「运行中」。环境是幂等的：重复点不会起第二份，已运行会直接返回。

顺手认识一下邻居：这一页里的 Agent Browser（无头浏览器自动化）和 KasmVNC Desktop（有头桌面）是互补的——前者适合纯网页抓取与点击，后者适合需要真实图形界面、真实渲染、真实桌面软件的场景。
完成标志：KasmVNC Desktop 卡片显示「运行中」，并出现进入桌面 / 操作指导的入口。
2

进入桌面，先认识三个区域

约 3 分钟

点卡片进入，浏览器新标签页打开 Web 桌面。第一次看到时建议按这个顺序认场：

① 桌面图标区——现在只有两个系统图标，稍后 AI 装完应用，这里会多出「Chrome」「飞书」。

② 左侧竖条——KasmVNC 的控制面板（展开后是剪贴板、上传下载、全屏、画质/帧率、快捷键）。想把本机的安装包传进桌面，就从这个面板上传。

③ 顶部与右下角——顶部细条显示当前会话信息，右下角是系统时间与电源角标；页面顶部工具栏上的「剩余时长」决定了你还有多少操作时间。

另外记得看桌面右侧那张黄色提醒，它把「文件放 /root」「用 get-apps.sh 装软件」「不会就问 AI Shell」三件事写在了明面上——本案例后面两步就是把这三条真的跑一遍。

完成标志：能看到完整的 Linux 桌面并能打开「文件系统」，说明图形会话正常。
3

先问 AI：这台桌面能装什么

约 1 分钟

回到 AI Shell（左侧 AGENTS → AI Shell），直接说人话。这句话很短，但它让 Agent 完成了一次「查清单」而不是「猜清单」：

AI Shell 提示词
可以一键安装哪些应用

看它的执行链：先 LOAD SKILL kasmvnc-app-installer（加载桌面应用安装技能），再 cat apps.conf 读沙箱里的配置清单，然后把别名整理成表格给你——7 个应用、可用别名、以及每个应用是什么。

为什么值得先问一句：这一步同时验证了两件事——沙箱活着、AI 与桌面是通的。如果这里就报错，先回去看环境状态，别急着装东西。
完成标志：拿到一张包含别名和应用名的清单表。
4

一句话装两个应用：Chrome + 飞书

约 8 分钟

这次说一句更贪心的：

AI Shell 提示词
安装 chrome、飞书

Agent 的反应很值得看——它没有闷头装，而是先判断「这是两个独立应用，可以并行」，再逐步跑安装，然后自己发现了异常并自愈：

中间那句「输出为空，可能是沙箱环境未启动，让我检查一下 kasmvnc 环境状态」是本案例最有含金量的一帧：Agent 依据实际命令输出做判断，而不是照着脚本往下念；确认环境在运行后它把并行改成串行，并做了一次幂等检查（已装的不重复装）。

最后的交付不是一句「装好了」，而是一张可核验的结果表：

它做了什么说明
装包按别名选择对应安装方式，落到 /root/Software/<app>/
建启动脚本生成 launch.sh，即使图标失效也能命令行拉起
建桌面图标 + 应用菜单图标与菜单项成对创建，两条入口都能启动
可执行校验逐项检查文件可执行权限，最后给一张四项全绿的表格
踩坑记录Chrome 的 RPM 包内含超大文件，标准 cpio 解包失败，改用 rpm2archive 解压后再配置脚本与图标；两个应用都装在持久化区，环境重启不丢
留意那个 4GB 的坑：Chrome 的 RPM 里有单体超过 4 GB 的文件，常规 cpio 解包会失败。这类问题以前要人肉翻日志，现在 Agent 换一条解包路径就过了——但你最好知道它发生过，出问题时才知道往哪看。
完成标志：结果表里「启动脚本 / 桌面图标 / 应用菜单 / 可执行」四项全部为绿。
5

回到桌面验收：F5 一把，双击启动

约 2 分钟

切回桌面标签页时你可能会发现——图标没出现。这不是装失败，而是桌面是已渲染的快照，需要手动刷新一次：

操作
在 VNC 远程桌面画面上按 F5 刷新
→ 桌面出现 Chrome、飞书图标
→ 双击图标启动

如果图标能看见但双击没反应，用命令行兜底（这也是验证「启动脚本真的可用」的办法）：

桌面终端 / AI Shell 均可
bash /root/Software/chrome/launch.sh
bash /root/Software/feishu/launch.sh

# 查看装了什么、卸掉不要的
get-apps.sh -l
get-apps.sh -u feishu
完成标志：桌面上双击 Chrome 能打开浏览器、双击飞书能进入登录页；两个应用都能重复启动，不报错。
6

把整套环境打包成一个链接发出去

约 3 分钟

平台内置的链接生成能力，可以把「预置了提示词的 AI Shell」或「某个作业环境」打包成深链，点开即进入对应的环境入口，不用被告知任何配置步骤。注意：这类直达链接进入的是打开者自己的 AI 开发者空间。三种预设场景：

类型链接形态点开后发生什么
aishell带 ?target=/aishell 的深链进入空间并打开 AI Shell，预置提示词已填好，对方直接接着干
jobenv指定某个作业环境自动部署并启动该环境，落到同一套工具现场
custom自定义完整配方（recipe）环境 + 提示词 + 初始命令整体复现，适合做团队标准工位

在 TOOLS → 链接生成 里挑场景、填提示词，还能叠加 UTM 渠道参数并生成二维码——贴在文档、群里、海报上都能扫。更实用的是可以把 npm install && npm start 这类命令编进链接，对方点开就自动跑起来。

安全提醒：直达链接带平台签名，与具体的实操入口 / 账号会话绑定，不要发到公开渠道；也不要把某条链接当作通用模板随意分发——对方点开进入的是他自己的环境入口，且这类签名链接可能有时效或额度约束。
完成标志：把链接发给一个同事（或自己用无痕窗口打开），对方无需任何配置即可进入对应的 AI 开发者空间环境入口。

安全与清理

三件要注意的事

  • 临时凭据的边界。首次进入时平台会询问是否把临时 AK/SK 同步到环境里，同意后命令行可直接操作云资源。这份凭据拥有当前登录用户在 IAM 上的全部权限，别用管着生产资源的主账号做这类实践，用独立的开发子账号更稳妥。
  • 数据存哪里。只有 /root 下的内容是持久化的（应用也装在 /root/Software），/tmp、系统目录重启即失。重要产物请及时下载到本地。
  • 链接别外传。带签名的直达链接等于门票，公开分享会连带消耗你的环境资源。

收工流程

  1. 把要留的文件下载到本地（用左侧控制面板的下载，或直接 cp 到可见目录再用文件管理器取出）
  2. 点页面右上角「释放」，弹窗里点「确认」——注意这一步不可撤销，容器与数据一起销毁
  3. 不要点「取消」，也不要只关标签页
一句话验收：页面回到开发者首页、倒计时消失，才算真的释放完。

进阶玩法

1 · 给 Agent 装上「眼睛和手」

无头浏览器只能读 DOM，遇到 canvas、视频、桌面软件、真实渲染就看不见了。把 KasmVNC 桌面当成 Agent 的操作台：让它启动应用、截屏、比对界面、跑端到端回归——「在云端验证你在本地看不到的东西」。

2 · 预置提示词的深链 = 会自我介绍的工位

生成 AI Shell 链接时把 Prompt 填进去（例如「你是本项目的测试工程师，先跑一遍冒烟用例再改代码」），对方点开的不是一个空白终端，而是一个已经知道该干什么的助手。

3 · 团队统一环境

环境模板（KasmVNC + 固定工具链）+ 一键安装清单（apps.conf 里的别名）= 可复现的工位。把 jobenv 链接放进新人手册，比写十页「环境搭建指南」有效。

4 · 桌面里跑 Agent IDE

清单里的 dsh（DSH Desktop）就是给这类场景准备的：在桌面里开一个图形化的 Agent 工作台，与 AI Shell 互补——一个负责「说」，一个负责「看」。

5 · 扩展到别的环境模板

「环境管理」里还有 IAC MCP Server、Agent Browser、HuaweiCloud DevKit 等模板。它们和 KasmVNC Desktop 用同一套 job-env-manager 生命周期，你在这台桌面上练熟的部署、分享、释放流程，可以原样套到别的环境上。
